## Patterns across events

**What has won or placed while using Mubit** (one confirmed Mubit-prize winner, so this is a thin sample):
- [F] Rentry (Mubit prize + 2nd overall) and joanie (2nd overall) share a shape. Each is an agent for an ordinary person or a small business. It remembers one specific user or customer across sessions or calls, and the demo shows that memory in action ("it remembered", "it still knows you", "remembers customer context") [H-23..H-26, H-37].
- [F] Rentry's stack was tiny: three sponsor tools, "nothing more". The winner credits "simplicity and usability" [H-24, H-25].
- [F] Frame Mog, a strong Mubit user, did not win but showed the learning live ("by session three ... visibly adapted"). Mubit staff praised that kind of use publicly [H-12, H-13].
- [I] At events where Mubit was only a sponsor, the overall winners mostly did not use Mubit (UM, Pop the Bubble 1st, Tech: Europe). Mubit credit and goodwill went to teams that made the learning loop *visible*. Bolted-on use was explicitly worth less at Pop the Bubble (+4 vs +10) [H-35].
- [F] Mubit people praise "self-learning", agents that talk to "actual people", "bold, innovative thinking" and, in people, "high agency" [H-11, H-13, H-47].

**How the brief changed:**
1. Apr 2026, memory SDK: "Execution memory SDK ... injects it into the next run"; "persistent memory across runs" [H-6, H-8].
2. May 2026: "learn from their execution ... improve accuracy after each run with just 3 lines of code", plugging into Vercel AI SDK. The primitives people built on were remember / getContext / reflect / recordOutcome, per a participant doc [H-22, H-28].
3. Jun 2026: "operational memory" must be core and verifiable (Pop the Bubble). Then "continual learning platform" plus **Minima**, which picks the cheapest model that clears a quality bar from feedback ({Tech: Europe}). This is the first move from memory to model choice and cost [H-35, H-43, H-45].
4. Oct 2026, Middleware: all LLM calls go through Mubit by base URL. Corrections become adapter "model updates" on task-adapted open models, with "quality, cost and latency side by side" [H-52, H-55, H-57, H-58].

**What stayed the same:** a feedback loop where outcomes change later behaviour, and judges who want to *see* it happen. That was before/after by session three in Apr, "campaign #1 vs #10" in May, and in Oct "Show a correction turning into a model update in your demo" [H-12, H-28, H-53]. The prize model moved from side bounty / credits, to bonus points, to Mubit's own event with $30k cash where using Mubit is mandatory and worth 25% of the score.

**[I] For tonight:** pick a recurring task with a cheap, frequent correction signal. Show the same input before and after a correction, live, with quality, cost and latency numbers. Keep the stack small. Point at a real user or task (usefulness is 25%).
